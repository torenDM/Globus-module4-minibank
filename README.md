# Модуль 4 - Переход на PostgreSQL
Перенёс клиентов, счета и операции MiniBank из `HashMap` в PostgreSQL. 
Запросы выполняю через JDBC, а таблицы, ограничения и индекс создаю миграциями Liquibase

### Запуск
1. Поднять PostgreSQL на `localhost:5433`. Имя базы и пользователя — `minibank`
2. Указать пароль в переменной `MINIBANK_DB_PASSWORD` в конфигурациях `Maven` и `Main` в IDEA
3. Выполнить `liquibase:update`, затем запустить `com.minibank.Main`

В `Main` два примера. При обычном переводе 100 балансы становятся 900 и 100. При переводе 50 на несуществующий счёт программа сообщает об ошибке, но деньги уже списаны. Баг сохранен по условию задания

### Индекс
Запустил один и тот же запрос по 60000 операциям до и после создания индекса по (account_id, transaction_date). В обоих случаях получил две строки. До индекса PostgreSQL использовал Seq Scan (3,058 мс), после - Index Scan (0,233 мс)

В `docs` лежат скрипт заполнения `seed-transactions.sql`, запрос `explain-transactions.sql` и оба плана - `explain-before.txt` и `explain-after.txt`. Запросы по товарам из презентации собраны в `products-practice.sql`.

# Модуль 5 - HTTP API
Добавил HTTP-сервер на Java `HttpServer`. 
Сервер читает JSON и возвращает HTTP-ответы, а переводы, создание клиентов и открытие счетов выполняет `BankService`

## Запуск 
1. Запустить PostgreSQL и применить миграции, как описано в модуле 4
2. В конфигурации `WebMain` указать `MINIBANK_DB_PASSWORD` и запустить `com.minibank.WebMain`
3. Сервер будет доступен по адресу `http://127.0.0.1:8080`

## Запросы

| Запрос | Поля JSON | Ответы                                                                                         |
|---|---|------------------------------------------------------------------------------------------------|
| `POST /transfer` | `fromAccountId`, `toAccountId`, `amount` | `200` - успех, `400` - неверные данные, `404` - счёт отсутствует, `409` - недостаточно средств |
| `POST /clients` | `name`, `email` | `201` - клиент создан, `400` - неверные данные                                                 |
| `POST /accounts` | `clientId`, `accountNumber` | `201` - счёт открыт, `400` - неверные данные, `404` - клиент отсутствует                       |

Пример перевода в PowerShell. `103` и `104` - ID моих тестовых счетов, для другой базы следует подставить свои

```powershell
'{"fromAccountId":103,"toAccountId":104,"amount":100.00}' |
    curl.exe -i -H "Content-Type: application/json" --data-binary "@-" "http://127.0.0.1:8080/transfer"
```

## Что проверил

В первой версии перевод выполнялся через `GET`. Открыл ссылку в браузере и перевёл 100 со счёта `103` на `104`, балансы изменились с 1000 и 0 на 900 и 100. 
Запрос на 10000 вернул `200 OK`, хотя в теле была ошибка `Insufficient funds on account 103`, после этого перевёл маршрут на `POST` и добавил отдельные статусы для ошибок

| Сценарий | Что отправил | Что вернул сервер                                    |
|---|---|------------------------------------------------------|
| Обычный перевод | `POST`, `103 → 104`, сумма `100` | `200 OK` - `Перевод выполнен`                        |
| Отрицательная сумма | `POST`, `103 → 104`, сумма `-10` | `400 Bad Request` - `Сумма должна быть больше нуля`  |
| Счёт отсутствует | `POST`, `999999 → 104`, сумма `100` | `404 Not Found` - `Account not found: 999999`        |
| Не хватает средств | `POST`, `103 → 104`, сумма `10000` | `409 Conflict` - `Insufficient funds on account 103` |
| Попытка перевода через `GET` | `GET /transfer` | `405 Method Not Allowed`, заголовок `Allow: POST`    |

Также проверил `POST /clients` и `POST /accounts` - оба вернули `201 Created`: создался клиент `4`, затем для него открылся счёт `105` с нулевым балансом. 
Попытка открыть счёт для отсутствующего клиента `64` вернула `404`.

### Примеры REST-маршрутов из презентации
- `POST /transfers` - создать перевод
- `GET /accounts/{id}` - посмотреть счет
- `GET /accounts/{id}/transactions` - посмотреть историю транзакций

# Модуль 6 — Hibernate

Перевёл `BankService` с JDBC на Hibernate. Клиенты, счета и операции по-прежнему хранятся в PostgreSQL. Схемой управляет Liquibase

В `FetchDemo` загрузил трёх клиентов и их счета. С `EAGER` Hibernate выполнил 4 запроса. После перехода на `LAZY` и `LEFT JOIN FETCH` хватило одного. 
Количество счетов совпало - 1, 1 и 2. Логи обоих запусков лежат в `docs/hibernate-eager.txt` и `docs/hibernate-lazy-join-fetch.txt`

В `OrphanRemovalDemo` убрал тестовый счёт из списка клиента и проверил, что строка удалилась из базы. 
В `HibernateDemo` проверил через `HashSet`, что клиенты с одинаковым email и счета с одинаковым номером считаются равными

Для запуска нужно применить миграции через `liquibase:update` и указать `MINIBANK_DB_PASSWORD` в настройках запуска. 
После миграции на Hibernate повторно проверил через `WebMain` создание клиента, открытие счёта и перевод
